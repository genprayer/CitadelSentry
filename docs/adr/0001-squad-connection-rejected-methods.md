# ADR 0001: Запрет неработающих способов подключения к Squad 10.6+ и закрепление единственного маршрута Server Browser

- **Статус**: `Accepted`
- **Дата**: 2026-11-14
- **Область применения**: Citadel Sentry (`citadel-seeder`), Squad 10.6.3+
- **Инициатор / Утверждено**: Владелец проекта Citadel

---

## 1. Контекст и проблема

Для реализации функции однокнопочного сидинга в Citadel Sentry («Начать сидинг» → автоматический вход на игровой сервер `[RU] CITADEL [AAS/RAAS]`, в том числе при 0 игроков) было проведено глубокое техническое исследование:
- Реверс-инжиниринг бинарника `SquadGame-Win64-Shipping.exe` (10.6.3).
- Анализ взаимодействия Steamworks, RedpointEOS и сетевого стека Unreal Engine 4.27.
- Трассировка выделенного сервера `SquadServer1` (`win-server`, GamePort 7787, BeaconPort 15005).
- Практические тесты игроками и диагностическими утилитами.

В результате исследования были выявлены неработающие и тупиковые технические направления, которые неоднократно предлагались или исследовались, отвлекая ресурсы проекта. Данный документ навсегда фиксирует отказ от этих подходов и закрепляет единственный подтверждённый архитектурный маршрут.

---

## 2. Запрещённые направления (Категорический отказ)

Агентам и разработчикам **строго запрещено** предлагать, исследовать или реализовывать следующие решения:

1. **Консольная команда `connect IP:Port`**:
   - В релизных (Shipping) сборках Squad 10.6+ движковая команда `connect` заблокирована разработчиками игры (OWI).
   - При попытке ввода игра возвращает ошибку: `Not a Valid command (connect)!`.
   - Прямой вызов команды через консоль невозможен.
2. **Автоматизация консоли через `SendInput` или эмуляцию ввода**:
   - Любые попытки симулировать нажатие клавиши открытия консоли (`~`), вставку текста `connect IP:Port` и нажатие `Enter` запрещены, поскольку сама консольная команда заблокирована в клиенте.
3. **Подключение через протокол `steam://connect/IP:Port` и Steam Server Browser по IP**:
   - Squad 10.6+ не перенаправляет IP-запросы от внешнего браузера серверов Steam в игровой движок. Клиент игнорирует параметры прямого подключения по IP.
4. **Использование параметров запуска `steam://run/393380//...`**:
   - Анализ секции `.rdata` бинарника доказал полное отсутствие CLI-параметров прямого подключения к сессии (`-connect`, `+connect`, `-join` и т.д.). Squad всегда загружает главное меню `MainMenu_Level`.
5. **Synthetic Steam Invite как готовое решение**:
   - Создание Synthetic Steam Lobby доставляет событие в `RedpointEOS`, и сессия EOS находится по ID.
   - Однако метод `USQOnlineServicesSession::OnSessionInviteAccepted` (VA `0x144acbb90`) лишь вызывает `OnSessionAccepted.Broadcast()` с параметром типа `FSQSessionSearchResult`.
   - В Squad 10.6 вся система подключения была переписана под Party/Beacon и требует объект `FSQServerItem`. Делегат `OnSessionAccepted` не имеет подписчиков ни в нативном коде, ни в Blueprint-пакетах, из-за чего игровое подключение (`ClientTravel`) не инициируется.

> [!CAUTION]
> **Запрет на повторные исследования:** Повторное исследование, тестирование или предложение любого из вышеперечисленных вариантов без новых воспроизводимых доказательств работоспособности и прямого письменного разрешения владельца проекта **запрещено**.

## 3. Единственный подтверждённый маршрут для дальнейшей разработки

Дизассемблированием `SquadGame-Win64-Shipping.exe` доказана единственная рабочая цепочка клиентского подключения:

```text
Server Browser (FSQServerItem)
       ↓
USQGameInstance::QueueForServer (VA 0x145ccfbc0)
       ↓
ASQJoinBeaconClient (BeaconPort 15005)
       ↓
OnClientConnectionAccepted (VA 0x145cc72e0)
       ↓
OnJoinSessionCountdownEnded (VA 0x145cc90d0)
       ↓
USQGameInstance::JoinSession (VA 0x145cc1460)
       ↓
ClientTravel / GameNetDriver (GamePort 7787)
```

### Направления для дальнейшей работы:
1. Исследование доступных штатных точек входа в цепочку Server Browser:
   - Изучение взаимодействия виджетов главного меню и классов `USQServerBrowser` / `FSQServerItem`.
   - Механизм **Favorites** (Избранные серверы) — исследование формата сохранения локального списка избранных серверов Squad (`GameUserSettings.ini` или локальный кэш EOS), чтобы сервер Citadel был гарантированно доступен в отдельной вкладке без глобального сетевого поиска.
   - Обход или переключение фильтра пустых серверов (**Show / Hide Empty Servers**), чтобы пустой сервер (0 игроков) отображался и был доступен для автоматического сидинга.

---

## 4. Главная цель проекта

**Одна кнопка «Начать сидинг» в интерфейсе Citadel Sentry → запуск Squad при необходимости → автоматическое штатное подключение к серверу CITADEL, включая сервер с нулём игроков.**

Никакого ручного поиска, никакого ввода IP пользователем, никакого использования несуществующей консольной команды.

---

## 5. Статус и исполнение

Данное решение принято как окончательный архитектурный инвариант проекта Citadel Sentry. Все агенты (Codex, Antigravity, Gemini) и контрибьюторы обязаны руководствоваться исключительно подтверждённым маршрутом.
